03 / Web development

From a clear plan
to a working website.

I build in clear stages, checking the work as it develops. The SDLC—Software Development Life Cycle—is a useful framework for taking a website or software idea from requirements through launch and ongoing care.

See the SDLC process ↓

The development lifecycle

Seven stages.
No mystery handoff.

Small websites may combine or repeat stages. We choose the right level of process for the project rather than adding unnecessary complexity.

01

Requirements

Define what it must do.

Document the audience, pages, features, content, integrations, accessibility needs, and project constraints. Separate essential launch features from future ideas.

Deliverable: an agreed scope and acceptance checklist.

02

Planning & architecture

Choose a sensible structure.

Plan the site map, page relationships, content model, technology, hosting, and any data or services the site needs. A simple brochure site should stay simple; accounts or payments need more careful planning.

Deliverable: a technical plan and milestones.

03

UX & interface design

Plan the experience before coding.

Create page layouts and interface states for desktop and mobile. Review navigation, readability, forms, and key user journeys, then align the visuals with the approved brand direction.

Deliverable: approved page designs and interaction details.

04

Implementation

Build the front end and features.

Write semantic HTML for structure, CSS for responsive layouts and visual styling, and JavaScript for interactions. If the project needs server-side behavior, a backend can process requests and connect to databases or trusted third-party services.

Deliverable: a working development version.

05

Testing & review

Check it across devices and tasks.

Test links, forms, interactive states, responsive breakpoints, keyboard access, contrast, and common browsers. Validate that agreed requirements work and fix issues found during review.

Deliverable: a reviewed release candidate and issue list.

06

Deployment

Prepare and publish the site.

Configure the hosting and domain, check production settings, publish the approved build, and test important pages and actions on the live site. Any launch depends on access to the client’s hosting and domain accounts.

Deliverable: a live website and handover notes.

07

Maintenance & improvement

Keep it useful after launch.

Monitor for issues, update content and dependencies as appropriate, keep backups and security practices in mind, and use real visitor feedback to plan improvements. Ongoing support is agreed separately with the project.

Deliverable: a clear plan for updates and future changes.

How a website works

What happens behind
the interface?

Front end — what visitors use

The browser reads HTML, CSS, and JavaScript to display pages and handle interactions such as navigation, theme selection, and form validation. The layout should adapt to phone, tablet, and desktop screens.

Back end — only when needed

A server can handle tasks that should not happen only in the browser, such as account access, booking logic, payment workflows, or protected data. Not every website needs a custom backend; a static site or a trusted hosted service may be a better fit.

Data, integrations & safeguards

Forms, analytics, content systems, and other services should be chosen for a real requirement. Sensitive information needs appropriate handling and secure services. Features, limits, and third-party costs are discussed before implementation.

Clear functions and handover

Each feature has a defined purpose, inputs, expected result, and useful error states. Before launch, we review the agreed behaviors together and document what the site does, how to update it, and what support is included.
